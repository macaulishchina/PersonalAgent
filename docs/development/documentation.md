# 文档维护约定

## 每类内容放在哪里

| 位置 | 内容 | 避免放入 |
| --- | --- | --- |
| 根 README | 产品定位、平台选择、入口 | 完整安装步骤、测试流水账 |
| `docs/README.md` | 按阅读顺序组织的导航 | 模块字段副本 |
| `docs/guides/` | 面向操作者的步骤、预期结果和排障 | 内部实现细节、历史验收数字 |
| `docs/reference/` | 安装选项、目录规则、模块索引 | 重复的新手流程 |
| `docs/development/` | 架构、接口、检查、发布和维护 | 私有实例状态 |
| `docs/archive/` | 有时间和边界的需求、计划与验收记录 | 冒充当前状态的旧结论 |
| 模块 README | 所属模块的字段、契约与专项说明 | 跨模块复制实现细节 |
| `AGENTS.md` | 仓库工程规则 | 用户手册 |

延续 `docs/` 目录，不另建并行的 `doc/`。模块 README 和技能可能随包交付，迁移前先检查打包声明及使用方。

## 编排与更新

- 一篇文档回答一个主要问题，开头说明用途和前提。指南按“操作 → 预期结果 → 下一步”展开。
- 同一事实保留一个详细说明来源，其余位置链接引用。根 README 和导航只摘要，不复制整章。
- 用户命令统一使用 `pa`，在需要时说明环境 PATH。项目文档只描述 Personal Agent 的独立安装和使用；其他仓库的别名、封装及集成由其自身维护。
- Windows／Server 与 Linux 命令分开，路径可替换且前后一致。新实例、已有实例升级和测试实例的操作明确区分。
- 当前支持与尚未实现的能力写清楚；验收数字留在有日期的归档，不散布到操作步骤。
- 历史材料保留证据，标注历史状态；旧私有报告路径用文字说明，不伪装成仓库可访问链接。
- 新文档加入导航或模块索引；移动文档同步修正相对链接、锚点和 AGENTS 中的引用。

## 修改后的检查

1. 检查相对链接、标题锚点和代码块闭合。
2. 对照现行 CLI 帮助、配置模板及代码核对命令，不为验证文档启动生产实例或调用模型。
3. 搜索被迁移的旧路径及废弃命令，确认没有遗留操作指引。
4. 运行 `git diff --check`，确认改动范围仅包含预期文档。

纯文档修改不重跑应用全量测试；涉及运行时技能、源码、依赖或测试输入时，按 [AGENTS.md](../../AGENTS.md) 执行相应检查。
