# 架构

本文说明职责和数据流；接口细节见[插件开发](plugins.md)，配置字段见[模块索引](../reference/modules.md)。

## 运行结构

```text
CLI / 网页
    ↓
conversation：会话、历史、附件、输入队列
    ↓
execution：公共执行接口
    ↓
Pi：唯一 Agent 执行循环和模型上下文
    ↓
模型供应商 / 受控工具入口
```

后台任务也使用同一执行器，与对话共用执行准入和用量保护。原生账号与 API 网关只是模型接入路线，不增加第二套 Agent。

## 目录与职责

| 目录 | 职责 |
| --- | --- |
| `src/assistant_runtime/kernel/` | 生命周期和能力契约；只依赖标准库与契约 |
| `src/assistant_runtime/api/` | 公开请求、插件上下文、工具与系统接口 |
| `src/assistant_runtime/app/` | 配置读取、依赖装配、管理进程与 CLI 命令 |
| `src/assistant_runtime/core/` | 对话、执行、模型、用量、任务等核心插件 |
| `src/assistant_runtime/plugins/` | 网页、语音占位、媒体及设备等扩展 |
| `src/assistant_runtime/platforms/` | 文件、ACL、锁、IPC、进程所有权与系统服务 |

内核范围不因部署组合变化。slim 和 standard 都交付核心代码与依赖，区别在于默认启用列表；未启用插件不导入、不实例化。

## 管理与业务进程

管理进程提供独立配置页、鉴权、配置修订事务及业务启停，不执行 Agent 工作。业务进程装配启用插件，处理对话、执行和任务。业务停止或配置损坏时，独立管理入口仍可用于修复。

配置分为面向使用目的的界面、统一配置服务和模块协议。模块拥有数据声明、默认值、语义校验、界面映射及更新生命周期；公共服务承担快照、校验、事务保存、冲突检测和应用协调。管理网页不依赖业务插件成功启动。

“保存并生效”先提交一致的 TOML／资源快照，再协调各模块准备、切换、清理；失败时恢复原有效设置。切换期间暂缓新请求，已开始的执行不取消、不重放。模型和连接在安全边界切换，并发降低只影响新准入。只有结构性设置要求显式重启或维护。保存、实际生效和待处理状态分开记录，手工编辑须显式应用；外部网关部署不冒充已完成。

配置服务拥有唯一对外 HTTP 入口：根路径为聊天页，配置页位于 `/config/`，聊天 API 与资源仍通过 `/chat/` 转发。聊天实现及认证仍归扩展，内核不依赖 Web 成功启动；进程间使用受保护的本机 HTTP 传输，控制通道提供当前端点。关闭聊天或重启业务不影响管理网页。

业务和工具子进程由管理体系拥有，后台启动机制归 `platforms/`。

CLI 是客户端：连接或启动已有实例。系统服务安装是独立操作，CLI 自动启动不会申请提权或注册服务。

## 对话与执行归属

`conversation` 依赖 `workfiles`、`execution`，不依赖个人助手。`assistant` 和 `cli` 使用公共对话，`web` 仍是扩展。个人助手提示、语音同步和设备状态协调留在 `core/speech`，仅在启用时装配。

对话持久化逻辑会话 ID、入口绑定、历史、附件、队列与执行关联。入口只使用会话 ID、请求 ID、问题 ID 和事件游标，不操作 Pi 原生会话。

同会话顺序执行，跨会话共享总并发和用量保护。模型上下文按会话复用；任务创建时保存来源会话，结果不随终端切换改变投递位置。重启后未派发输入中断、未知执行不重放。

详细契约：[对话](../../src/assistant_runtime/core/conversation/README.md)、[执行](../../src/assistant_runtime/core/execution/README.md)、[Pi](../../src/assistant_runtime/core/pi/README.md)。

## 插件、平台与安全边界

扩展仅通过 `assistant_runtime.api` 访问自身上下文、声明资源和能力，不能持有宿主或其他插件的私有实现。静态平台声明用于目录展示、配置校验和启动检查；普通 Windows 与 Server 共用 `windows` 认证。

平台层拥有系统机制，业务模块拥有事务、执行状态、额度和重试策略。Windows ACL、命名管道与进程所有权不能由 Linux 模拟测试代替实机证据。

AI 调用在派发前经过持久化用量准入；子任务、继续执行和模型回退共享工作额度。计量失败阻止新 AI 调用，未知外部操作不重放。

普通 Web／CLI、对话和 Agent 任务使用完整本地权限，插件属于可信代码；工具元数据和调用者身份检查不能当作 OS 隔离。显式使用 `ExecutionControl` 的受控上下文另有 Windows 文件代理和 LPAC 固定 cmd 检查后端，能力及实测范围见[受控执行接入](controlled-execution.md)。它不支持任意 shell／工具链，Linux 受控资源后端明确拒绝，普通执行不会自动进入该隔离路径。

## 版本与装配边界

内核及核心插件共用一个发布版本，扩展维护自己的版本和兼容范围。`VERSION` 是内核和 Python 包版本的唯一来源；`release.json` 描述公共 API 与实例数据格式，`owners.json` 只登记内置插件身份和模块位置。插件自己的 `plugin.json` 统一声明版本、依赖、平台及默认实现；配置界面描述独立保存在 `configuration.json`。

公共 `api/releases.py` 负责标准库可读的静态契约和 manifest 生成；`app/versions.py` 负责版本范围策略，装配层协调平台、依赖和版本检查。管理目录与升级预检读取静态数据，不导入候选插件代码；实际加载再核对运行时声明。内核继续负责依赖图与生命周期，不承担安装、版本解析或升级流程。

实例在业务打开存储前记录最高使用版本，健康启动后记录上次成功版本。记录与配置修订、业务数据迁移各有职责；代码替换需要显式重启，不经过配置热更新接口。维护流程与保护边界见[发布与切换](release.md)。

## 配置与持久化

实例拥有 `management.toml`、显式组合的 `config/`、私有凭据及 `state/`。插件拥有各自业务表和查询实现，外部包仅在其私有目录持久化。配置、业务历史和模型上下文的生命周期分别管理。

已有数据迁移保留会话、附件、任务、通知和执行证据；先备份，再事务转换。具体操作见[日常维护](../guides/operations.md)，工程约束见 [AGENTS.md](../../AGENTS.md)。


## 工具服务共享

每个 PA 实例在 Pi 适配层使用一个仅监听本机的 Streamable HTTP 入口。已启用的
内置工具按原命名空间装配一份，主对话、后台任务和 slim 的 Pi 会话复用这份服务。
适配层按执行绑定凭据和工具权限，仍经本机控制通道调用所属插件的能力。
插件继续持有业务状态、并发规则和操作回执。

共享入口同时限制实例和单执行会话的在途请求。Pi 只并行调度可信内置、明确声明为只读且非破坏性的工具。
跨执行的业务互斥由资源所属模块负责。实际案例与验证范围见[共享工具服务并发审查](shared-tool-concurrency.md)。

Pi 会话仍有独立进程、上下文和工作目录。关闭会话撤销其凭据；取消和断线只影响
关联调用。重启后按保存的权限重新生成本机连接配置。第三方 MCP 保持其自身的
连接和进程生命周期。

## 结果留存、交付与恢复

`api.results` 提供中立引用与读取错误；`workfiles` 拥有收到的内容、授权读取、
容量和生命周期，不维护第二份业务状态。`execution` 关联权威最终结果和操作证据，
Pi 适配工具正文与图片，任务及通知仍拥有投递身份和结果通知权。Web、CLI 和插件
都经 `FileRequest` 读取同一版本。过程轨迹仍有界。

结果身份由执行、轮次/调用派生；先落内容再提交引用，同一身份变更内容拒绝覆盖。
模型只看短正文或标明节选的预览，通过 `read_result` 追加读取；既有历史不按每轮
摘要重写。默认永久，自动保留可选 7/30/365 天；所属执行、任务及通知分别确认保护
关系能否解除。未知状态保留保护，缺失/过期/损坏只恢复读取，绝不重放原操作。
Windows 受控 `finalize` 仍是独立发布语义，普通收到的结果不借用或绕过该边界。

插件管理页面通过随包静态声明和 SDK v1 接入，详见 [管理页面规范](plugin-management-pages.md)。
配置核心插件负责管理员外壳、页面装载、草稿与事务，插件负责页面组件和业务动作；
静态发现不构造业务实例。页面不是模型工具，也不是恶意插件沙箱。
