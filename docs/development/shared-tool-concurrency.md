# 共享工具服务并发审查

审查基线为 `93cc5e0`。范围包括 31 个内置插件、实例登记的两个第三方 MCP、Web、CLI、PP、任务调度、插件间调用和 Pi 原生工具。修复按下表顺序推进。复现使用本机合成服务。

| 顺序 | 发现与证据 | 修复或验证边界 |
| --- | --- | --- |
| 1 | 媒体整理在取消已确认后仍可建目录。单文件转存和目录整理走不同队列，可能同时检查、写入同一目录。 | 统一最终派发与取消判定。核对 native、OpenList、本地整理、转存、下载及批处理。共享实际目标的写入保护，已派发的未知操作只读核对。 |
| 2 | 新搜索加入正在取消的同键请求后也被取消。并发合并沿用首个调用者的截止时间和付费用量归属。 | 先摘除取消中的请求。正在执行的付费请求按工作身份合并，完成缓存仍可共享。单个等待者的超时独立处理。 |
| 3 | 设备查询取消把另一查询已经发布的可用状态改成异常。 | 取消只结束等待。使用探测发起顺序阻挡过时状态；设备动作继续使用设备及资源租约。 |
| 4 | PP 快速连续重连时，新连接能在原连接清理完录音和收据前开始运行。 | 按设备协调交接。重复关闭等待同一次清理，其他设备仍可连接。 |
| 5 | 阿里语音建连阶段重复计数，两个建连即可耗尽四个名额。 | 一个建连或活动流各占一个名额；失败、关闭和取消后验证归还。 |
| 6 | 13 个 Web SSE 握手能同时通过 12 个连接的上限。慢上传持有全局上传锁。 | 握手前占位，传输前做有界准入。锁只保护上传提交与清理。 |
| 7 | Pi 并行调度与只读恢复使用不同的只读判定。 | 统一可信内置工具的判定，第三方声明不提升并行权限。 |
| 8 | 共享 HTTP 工具入口只有总请求上限。第三方 MCP 和 Pi 文件／命令的独立会话无法防止两个执行修改同一业务对象。 | 验证单调用者占满入口的风险和不同执行隔离。第三方按实际设备或资源验收，Pi 文件和命令继续由执行范围及任务资源协调。 |

对话、任务、通知、事件、用量、工作文件、记忆和配置已有队列、版本、事务或锁。设备动作已有租约。其余插件未发现需要为共享工具服务增加全局串行的证据。独立 Python 插件未在当前实例安装。

外部验收另行记录。合成测试可以证明程序内的并发、取消和状态交接，真实第三方 MCP、设备和网盘还需各自验证。

## 当前保护边界

- 同账号的媒体写队列共用写入保护。目录移动或回收可能影响后代，写锁粒度采用账号。不同账号的队列处理可以重叠，独立浏览和下载无需等待云端写锁。提交状态和目标凭据保存在现有操作记录中，重启后也可用于防冲突与只读核对。
- 共享 HTTP 保留 256 个实例请求上限，并限制单执行会话最多 32 个在途请求。Web 的 12 个 SSE 名额含握手阶段；最多 4 个上传并行接收，单张 10 MiB，收包最长 90 秒。
- PP 同一设备已有交接时，额外握手收到冲突响应，后续可重连。其他设备仍按自己的连接名额工作。语音服务关闭时等待清理正在建连的请求，避免提前归还名额。
- 第三方 MCP 保留其独立连接。PA 不掌握外部工具的物理设备身份、写入锁和操作回执。当前实例的 `mobile_mcp` 应单独验收同一台电视的跨执行控制；`codex_resets` 应单独核对重复查询的限流。Pi 原生文件和命令继续使用已有工作区与任务资源声明，独立工作区隔离正常文件产物。

- 已覆盖取消与最终写入竞争、批次取消与子项登记、网盘目标冲突、本地发布重启核对、搜索等待者与用量归属、设备晚到快照、PP 握手和旧连接帧、语音占位及 Web 准入。
- 共享 MCP 通过本机 HTTP／IPC 并发测试。真实 Pi 配合合成模型服务验证主对话和后台任务，以及明确只读、写操作、声明冲突和缺少声明四种调度情况。
- 全量运行暴露了 Apple Home 快照回归及 Pi 批次样本缺少明确的非破坏性声明，两处修正后已定向复验。模型预设另有三个现有测试失败，涉及多协议预设的字段和必填协议选择，相关实现与测试未在本轮修改。
- 未调用真实网盘写入、供应商或设备，第三方内部并发仍待实测。
