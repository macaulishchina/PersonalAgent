# 业务操作结果与媒体目录操作

框架 `0.4.31`、media `1.2.0`，公共插件 API 仍为 2，数据格式仍为 1。
已有插件不需要批量改写；media 使用新增可选声明，要求框架至少 0.4.31。
这是开发实现说明，不代表已经部署或通过真实网盘验收。

## 业务结果与执行结果

模型执行结束，只说明本次 Agent 已停止。插件拥有自己的业务回执，任务通过
公共只读能力观察它们。存在未确认操作时，不能依据模型的“已完成”报告业务成功。
任务保留原模型报告、关联操作和最新观察，业务账本仍只有所属插件的一份。

插件可在 `PluginDefinition` 声明 `operation_request`，类型必须同时出现在 `provides`。
应用将其绑定为只读请求 `("operation_outcomes", {"run_id": RUN_ID})` 的来源，
不访问插件实例或数据库，不注册新的模型工具。查询只能读取本地回执，不能启动 Agent、
执行云端写入或在查询中重做业务。

返回 `operations` 数组，每项包含：

| 字段 | 约束 |
| --- | --- |
| `id` | 所属插件内稳定且唯一的操作标识 |
| `revision` | 有限、非负、单调递增的观察版本 |
| `state` | pending、completed、failed、cancelled、unknown、waiting_user |
| `responsibility` | system、user、none |
| `summary`、`code`、`next_action` | 可选安全说明，不包含凭据或供应商原始正文 |

一次最多 1000 项；标识最多 200 字符，说明字段最多 1000 字符。关联证据消失、版本
倒退或所属能力不可用，会保留未知结果。没有关联操作的普通任务保留原流程。
未实现此声明的旧插件继续可用，但框架不会虚构它们的业务核验能力。

业务 pending 时，任务等待插件核验，Agent 不再占用执行名额；unknown 报告结果待核验。
只有 waiting_user 且存在实际处理事项时才提示用户处理。任务状态和业务状态分别保留，
Web 详情分别呈现。未核验操作阻止重新执行，不能重复“继续任务”绕过。
关联任务的 completed 事件等待明确业务结果；明确失败/部分失败走 failed 事件，
pending、unknown、waiting_user 不触发成功的后续任务。无关联操作的任务保持原语义。

任务复用已有 worker 读取关联回执，不调用模型。收敛后修改同一通知，更新失败保留
重试标记。已交付的对话/语音不回放，任务详情保留最新事实。没有通知插件时可查询
结果；没有任务插件时 media 可独立运行；没有 Web 时公开能力仍可用。
无需新增权限引擎、调度器或消息插件。

## 整目录删除与转存

明确请求删除整部剧时，定位配置范围内的真实目录 ID，预览一个
`{"action":"trash","folder_id": FOLDER_ID}` 变化，再 apply 返回的计划。
只移动到回收站，不永久删除，不允许删除配置根目录；明确整目录授权不需逐集确认。

计划冻结目录清单，提交前重新检查；对象或子对象已有未结束操作、内容变化、越界时
拒绝写入。使用一个目录写请求。恢复要求本插件保存的删除与回收条目标识，并核验
原位置及完整清单。本轮目录 trash/restore 面向原生 Aliyun/Quark；OpenList 和本地
保留既有文件管理范围，不虚构目录能力。

完整分享目录转存使用 `transfer_media(object_type="directory", file_id=FOLDER_ID, ...)`，
源分享和目标须属同一供应商。目录不接受单集、改名或版本参数，保留子目录、字幕与
其他文件；只选部分集时仍用文件转存。转存不意味着本地下载。

整目录一次提交，通过目标根 ID 或异步任务回执确认身份，再核对相对路径、类型、
文件大小，以及源端实际提供的哈希。不能只凭同名目录证明成功。清单最多 1000 项、
16 层；超限明确失败，不截断清单后继续写入。

回收站当前目录与原父目录由适配器明确区分。核验始终检查对象 ID、名称、类型，
文件还检查大小；双方有哈希时检查哈希。原父目录由保存的删除证据负责，不拿回收站
所在位置冒充。失败保留具体字段、预期及观察证据，不忽略身份校验。
如果回收站返回不同父目录，还要求供应商删除时间与本次持久化提交时间相符；
缺少这项证据的历史记录继续保留未知，不为恢复现场直接放宽校验。
协议参考：[阿里云 ListRecyclebin](https://help.aliyun.com/en/pds/drive-and-photo-service-dev/developer-reference/api-pds-2022-03-01-listrecyclebin)。

## 恢复、取消与通知

写前保存提交标记。响应丢失、重启或取消后，只读取已提交操作的回执，不重新提交。
没有可信目标 ID 的目录转存保留未知，不按名字猜测。`verify_media_operation`
对未知库/目录操作只核验已提交步骤，不执行剩余删除。

media 复用已有 worker，对有提交证据的未知库操作、目录转存做最多三次延迟只读核对。
无证据或次数耗尽时保留原始错误、回执和未知状态供核查，不按超时清除。
显式 resume 仍遵守既有授权；查询不等于继续。取消停止未提交步骤，不回滚已发动作。
目录实际已完成时如实记录完成，并保留取消请求，不为显示“已取消”再执行反向动作。

关联媒体事件随任务汇总；独立未知结果说明实际原因，不要求用户查询不透明 ID。
核验完成后更正原通知，避免残留失效的“需要处理”。

## 验证和上线边界

合成验证覆盖契约、目录变化/越界、单次写入、响应丢失、重启、取消、只读核对上限、
任务报告与回执冲突、通知更正、插件裁切和真实 Pi 配合本地合成模型的链路。
这些验证不替代真实 Aliyun/Quark 账号验收。

真实验收使用专用分享与目标目录，分别验证嵌套目录/字幕转存、目录回收及原位置恢复，
读回 ID、相对清单、大小/哈希及回收条目，记录供应商和实际结果。不使用日常电视剧
进行验收，不自动迁移、清理或重放历史未知操作，不在开发中部署。
历史异常只能由原始证据及只读核验确认；新实现不能补造当时缺失的字段。
