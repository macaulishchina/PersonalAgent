# 配置模型与访问

前提：已完成[安装与首次启动](deployment.md)，配置网页正在运行。

## 登录配置网页

默认地址为 `http://127.0.0.1:8047/config/`。口令读取命令：

```text
pa configuration token --management <实例目录>/management.toml
```

忘记口令时将 `token` 换成 `reset-token`，在服务器本机重置。路径含空格时加引号。

| 入口 | 默认监听 | 地址配置 | 口令 |
| --- | --- | --- | --- |
| 系统配置网页 | `0.0.0.0:8047/config/` | `management.toml` 的 `host`、`port` | 独立管理员口令 |
| 可选聊天网页 | 同一端口的 `/` | 在插件页启用 Web；对外地址仍由 management.toml 设置 | 独立聊天口令 |

远程访问使用服务器 IP，只需放行管理端口。配置页始终由内核管理服务提供；Web 未启用、业务故障或重启时仍可访问。聊天插件只使用本机内部传输，默认自动分配端口，无需额外配置防火墙。旧实例升级时将 [web].host 改为本机地址（如 127.0.0.1），port 可改为 0；它们只放在高级设置中。公网访问使用 HTTPS 反向代理并配置管理服务的受信来源。

## 配置一个可用模型

登录后从“概览”的配置进度进入“模型与账号”，按三个页签完成：

1. **连接**：点击“添加连接”，选择原生账号或 API 连接。原生账号可录入 API Key，向导会一起准备账号、连接和私有凭据；OAuth 先保存连接，再在账号授权区登录。两种方式都随 PA 使用已安装的 Pi 协议库，无需单独部署模型转发服务。
2. **模型库**：点击“添加模型”，选择连接并填写供应商模型 ID、在 PA 中的名称（支持点号，例如 `deepseek-v4.1-flash`）。系统自动读取能力资料，编辑栏直接填写上下文、模型最大输出、图片和结构化结果等参数，可继续修改。“思考设置”中启用当前连接支持的档位，再选择默认思考模式；默认使用“自动”。模型无需人工验收标记即可选择使用，实际请求仍检查连接、凭据和参数。
3. **用途**：选择主对话模型、默认思考深度，开启模型服务。任务默认跟随主对话，记忆在启用时配置独立绑定。
4. **保存并生效**：查看生效结果，正在进行的对话会先完成这一轮。进入 `pa` 发送消息，检查回答及执行结果；登录成功或模型目录可见不等于调用已经验收。

API 连接的新增和编辑使用同一表单：选择预设时自动提供地址和协议，通常只需填写 API Key；选择自定义接口时填写协议、地址和 API Key。认证请求头默认按协议选择，特殊覆盖和会话请求头收在“高级协议设置”。预设、自定义接口、原生账号不会混填同一组字段。

普通模式由 PA 自动管理凭据存储名称，无需填写“凭据引用名称”。已有密钥显示已配置，留空保持、输入新值替换。只有需要使用已有凭据或服务器环境变量时，才展开“高级认证来源”切换来源；引用模式不显示 API Key 输入框。切换预设导致目标地址改变时需要重新填写对应密钥，原有密钥不会删除。修改共享凭据的连接会使用独立引用，避免连带改变其他连接；所有变化仍在“保存并生效”时提交。

连接和 API Key 可以先单独保存，无需添加模型、指定用途或先通过测试。连接和账号名称支持大小写英文字母、数字、下划线和连字符；PA 模型名称还支持点号。名称均以英文字母开头，最多 64 个字符，同一列表内不能仅以大小写区分。

连接卡片及“编辑连接”中可执行“测试连接”；原生账号对应“检查授权”。API 连接测试和模型查询直接使用当前草稿，无需先保存；优先使用当前输入的 API Key，未填写时读取该连接引用的已保存凭据，不受其他连接草稿影响。测试不会保存配置、保存密钥或启用连接；字段错误会指出具体项目，结果区分目录连通、认证失败、接口不支持、限流及网络错误。原生账号授权仍通过独立账号流程建立。原生账号检查仅反映本地认证状态，不能代表供应商网络或推理已通过。

“添加模型”中先选择连接，再点“查询模型”。左侧目录可搜索并选择，选中后填入模型 ID，并在名称为空时给出可修改的 PA 名称；右侧仍支持手工填写。切换连接会清空旧模型 ID 和目录，迟到的查询不会覆盖新选择。目录缺失、查询失败或只返回部分模型时，可使用供应商提供的准确 ID。选择目录模型不会自动启用连接；API 目录检查不调用推理。

能力识别不发送推理请求，也不需要先保存 API Key。原生连接优先读取已安装 Pi 的模型目录，公开规格由随应用发布的 models.dev 本地快照补充；网络不可用不会阻断配置读取。公开规格不是当前中转的实测保证。没有自动识别到资料时，“查找并选择能力参考”会按当前模型名搜索所有服务商的记录，同名优先。可修改关键词，在下拉框中选择候选，查看上下文、输出及能力预览，再点“采用并填充”。下拉框一次列出全部匹配项，顶部输入框可即时过滤服务商或模型；清空过滤恢复全部，支持方向键、Enter 选择和 Esc 收起。根据上游 `canonical_model_id`（原始模型归属）识别原厂目录并优先展示，不按模型名称或厂商名单猜测。搜索 `deepseek` 后，在下拉过滤框输入“原厂”或“官方”即可筛选 DeepSeek 原厂记录；搜索也匹配上游原始模型 ID，因此可以找到使用不同接口别名的原厂记录；预览会显示原始归属，采用资料不会更换调用时的模型 ID。没有原厂记录时会明确提示。标签区分原厂目录、其他目录和归属未标注；其他目录不等于非官方，只表示公开资料的目录归属，不代表当前连接已获官方认证。搜索和选择不会改配置；采用后留在页面草稿，统一保存才生效，也不会更换连接或供应商模型 ID。没有合适资料时可以保留“未知”并保存模型，或直接手动填写。

“自动”与“关闭思考”不同：自动遵循当前适配器默认行为，API 连接不主动发送思考参数；关闭只有在明确支持时才能选择。原生路线由 Pi 将支持的档位映射为供应商参数，包括适配器提供的预算或自适应机制。不会把仅有“支持推理”声明的模型猜成支持所有档位，也不提供尚无适配实现的任意预算控件。上下文以 token 计数，输出使用模型上限与实例预算中较小者；原生账号显式的 `output_limit="model"` 例外仍适用。

“采用并填充”或“重新填充资料”将资料中已知的参数直接写入当前表单，替换原值；资料未提供的字段保持不变。填入后可以正常编辑，保存才生效；不再区分自动值和覆盖值。模型最大输出是规格，辅助／执行输出上限是运行预算，实际调用取较小者。思考档位从 models.dev 的 `reasoning_options` 明确列表中导入，受当前协议适配范围约束；API 连接的 OpenAI 协议可自动填入 `low/high/max` 等已声明档位，Pi 原生连接以 Pi 的实际映射优先。开关和 token 预算不会被猜成深度档位；仅有“支持推理”声明时不猜测档位，可按供应商说明勾选。取消默认模式所用的档位时，默认模式回到“自动”。修改模型 ID 或连接会撤销页面中的旧快照；其他页面修改连接地址时，保存校验会要求相关模型刷新快照。真实工具执行继续使用[模型验收流程](../../src/assistant_runtime/core/models/README.md#acceptance)。

模型页签之间切换保留草稿。“保留修改”只将修改留在当前页面，点击底部“保存并生效”才提交；“取消编辑”或 Esc 会撤销本次侧栏编辑，保留其他草稿。切换到另一配置页面时，可选择继续编辑、保存并切换或放弃并切换；保存失败会保留草稿并停在当前页面。账号登录、退出属于单独的即时操作，需先保存配置。

低频参数放在“高级”页签：超时、上下文与输出限制默认折叠。供应商地址与 API Key 在对应连接中维护，各连接相互独立。

ChatGPT 原生账号使用独立 OAuth 授权，并显式设置 `output_limit="model"`。账号、模型能力和具体字段见[模型模块](../../src/assistant_runtime/core/models/README.md)。

也可在选定实例后使用 CLI 管理已声明的账号：

```sh
pa model-accounts providers
pa model-accounts login --account NAME
pa model-accounts status --account NAME
pa model-accounts catalog --account NAME
pa models check
```

跨机器 OAuth 登录时按终端提示转发回调端口。密钥使用页面私有凭据入口或实例 `.env`，不写入普通 TOML；不复制其他应用会轮换的登录令牌。

## 连接如何生效

预设与自定义 API 连接均由 PA 直接调用供应商接口；OAuth／原生账号使用同一 Pi 协议库。供应商的地址、凭据和模型声明是唯一配置来源，没有第二份转发服务配置需要同步。

“测试连接”验证目录接口，不能代替模型推理或工具执行验收。保存可以分步完成：先保存连接，再添加模型，最后选择用途。启用时校验凭据和适配能力；失败会保留已保存内容及原有效配置，可修正后重试。

模型库每行的“测试模型”会直接使用当前页面的模型、连接和凭据设置发送一次简短文本请求，无需先保存。结果显示回复、耗时或失败原因；最长等待 45 秒，使用模型的正常辅助输出预算，不自动重试或切换模型。测试不会读取对话历史、调用工具或更改配置；文本回复成功不代表图片、结构化输出或工具调用已通过测试。原生账号使用其支持的输出方式，消耗仍计入统一用量保护。此操作需要业务服务及 models 插件就绪，模型服务总开关或连接无需先启用。

## 后台任务的模型与思考深度

进入 **任务与通知 → 安排任务**。默认模型可以保持“跟随主对话”，不要求配置任何推荐项。
任务创建时保存具体模型与深度；调整推荐或主对话不会改写已有任务。

“模型推荐项”可添加自定义名称、已登记模型、思考深度、推荐理由与适用场景。
主模型发起任务时可选推荐，也可直接选模型；没有固定四档或隐含排名。
编辑框的思考深度仅列出所选模型支持的值。模型库显示主对话和推荐名称标签，
推荐引用同一个模型库条目，不复制供应商配置。

主对话的 `auto` 由供应商决定；任务的 `auto` 表示发起模型需要选择原生深度。
漏填时先沿用主对话的具体深度；如果主对话也是 `auto` 且模型提供可调深度，
工具会要求发起模型补全，尚未创建任务。没有可调深度的模型继续使用 `auto`。

可选的决策辅助位于高级设置，必须启用 `decisions` 插件才有建议。
关闭、缺席或不可用时使用原有效选择，用户明确指定和固定配置不会被修改。
调用失败直接失败；不存在备用模型自动切换。取消、结果未知及共享用量保护保持有效。

旧四档及回退字段不再接受。升级实例配置时删除 `tasks.model_policy` 中的
`profiles/default_profile/fallbacks` 以及模型条目下的 `fallbacks`，按需要创建推荐项；
这不要求重写历史任务或操作证据。

## 页面怎么选

“概览”显示首次配置进度与常用入口；工作空间按对话与执行、任务与通知、文件与记忆、连接与设备组织。实例维护与功能管理单独放置。首次使用只需接通模型；高级设置默认折叠，未启用功能的设置可按需展开。模型和连接列表支持搜索；用量预警直接输入百分比，错误显示在对应字段旁。“说明”提供字段来源、范围及恢复默认入口。

在“功能与插件”的能力卡片查看平台认证和依赖，通过“配置”打开扩展自己的页面。关闭插件保留已有设置。Windows／Server 只能启用已认证 Windows 的插件；已有不支持配置可取消插件并修正依赖，系统不会自动删除它们。

插件自动识别当前系统。只有已启用插件在当前平台存在多个实现时，才显示“平台默认实现”下拉框；单一实现无需设置。保存了不可用的实现时仍会显示修复入口，可恢复默认。插件只加载选中的实现，不可用时明确报错。当前本机音频在 Linux 使用 PipeWire、Windows 使用 WASAPI；本机摄像头在 Linux 使用 V4L2、Windows 使用 DirectShow。设备身份仍在“连接与设备”中单独配置，选择实现不会自动改变设备。

## 保存与生效

修改后点击“保存并生效”。无需重启的设置先应用，完成后提示保存成功。模型、账号凭据和连接在安全边界切换，保留会话与历史；降低并发不会取消已开始的工作，修改预算不会清零用量。

如果还有插件启停、固定主语音绑定等需要重启的修改，页面只询问一次是否重启：

- 选择“重启并生效”，重启业务并应用剩余修改；当前工作会中断，未知结果不会自动重做。
- 选择“暂不重启”，只把剩余修改保留在“变更记录”和页面中，刷新后仍可继续编辑、再次保存或放弃。已经生效的修改不会继续显示为待保存。待重启修改不会提前写入实际配置，也不会因普通后台重启自动应用。

更新失败会给出提示并保留原运行配置，可再次点击“保存并生效”重试。无法恢复的模块会停止接收新请求；后台记录诊断和恢复信息，失败候选不会因后台重启自动重试。相互依赖、无法分开校验的修改一起等待重启，避免只应用一半。

手工修改文件后，通过配置页或 CLI 校验并应用；运行进程不监视半写入文件直接热更：

```text
pa configuration check --management <实例目录>/management.toml
pa configuration apply --management <实例目录>/management.toml
pa configuration status --management <实例目录>/management.toml
```

普通配置、静态凭据和已选技能纳入配置版本；OAuth 登录／退出是独立账号操作，不随配置回滚。管理事务和恢复细节见[配置模块](../../src/assistant_runtime/core/configuration/README.md)。

## 配置文件在哪里

实例目录保存 `management.toml`、`config/`、`.env` 和 `state/`。其中 `config/config.toml` 显式引用片段；`root` 决定数据位置，移动配置时保持其指向不变。

工作区、文件存储、MCP 注册表和网页口令等相对路径均以实例目录为基准。环境变量凭据优先于 `.env`，页面会显示来源；修改文件不能覆盖进程外部注入的环境变量。

本次整理保持现有 TOML 键和 include，不自动改写已有实例，也不迁移会话、任务或账号数据。需要调整旧实例的启用组合时，按[维护指南](operations.md)生成显式候选，审查差异并备份后应用。

### 清理旧模型验收字段

旧配置中的 `model_api.entries.<名称>.execution_validated` 已移除。升级前备份配置，删除各模型下的这一字段（无论值为 true 还是 false），再校验并应用；其余模型参数和业务数据保持不变。模型列表不再显示验收标签，“测试模型”继续提供即时文本推理检查，测试结果不控制启用。

### 网页密码

配置管理页面与聊天网页使用各自独立的密码，统一接受 6–256 个字符，无需大小写或数字组合，也无需短密码额外批准。首尾不能有空白，不能包含换行或空字符。管理密码通过顶部“修改密码”修改；聊天密码通过聊天网页插件配置中的“聊天网页访问口令”修改并保存生效。修改后旧登录会话失效，需要重新登录。

### 插件运行异常

配置页会持续刷新插件健康状态。插件启动失败、运行降级或报告错误时，各配置页面顶部显示插件名和诊断原因，恢复后自动消失。“配置已生效”表示设置已应用，不代表全部插件健康；请同时查看运行提示。状态连接中断时会明确提示，不继续显示旧的正常状态。

记忆插件需要本地嵌入模型。首次启用前，在仓库目录运行 `python scripts/prepare_memory.py --config instance/config/config.toml`（使用 PA 的 Python 环境）。脚本下载模型并在临时索引验证，不修改现有记忆，也不调用云端整理模型。运行时只读取本地文件；准备成功后插件会自动重试恢复。若模型源网络不可达，可在准备进程中指定可访问的 `HF_ENDPOINT`，无需改变运行时配置。

记忆检索按语义相关度排序，最多返回 8 条，并使用当前本地嵌入模型的最低相似度 0.5 过滤弱匹配；没有相关记忆时返回空列表，不以低相关记录补满结果。此分数不是正确率或概率；更换嵌入模型时需重新验证阈值。

### 自动记忆整理

在“文件与记忆”启用记忆和“自动提取记忆”，并在模型用途中指定记忆整理模型。后台每轮处理后等待 5 秒检查新输入；只有所有 Web／CLI 会话都空闲、没有待执行消息时才调用整理模型，并非每 5 秒必定调用一次模型。该轮询间隔不提供配置项。

范围是当前实例的所有 Web／CLI 会话，按已完成轮次分别整理用户文字，包含补充和澄清回答；助手回复、工具输出、后台任务报告和附件内容不作为自动提取证据。取消、中断或结果未知的轮次不整理。整理批次保留会话、消息、请求、执行 ID 和入口，重发同一请求不会重复入队，重启复用已完成的 Mem0 整理回执。

升级首次启用此链路从新增消息开始，不自动扫描旧历史。关闭自动提取期间的新增输入不追溯；已经入队的批次暂停，重新开启后继续。忘记或更正记忆会使之前的待处理来源失效，避免旧输入重新生成已删除的内容。会话切换或退出 CLI 不改变整理归属。

来源按会话保留，但记忆不是按会话隔离：个人偏好供同一实例使用，项目记忆按工作区隔离。技术细节和针对性验证见[记忆模块](../../src/assistant_runtime/core/memory/README.md)。
