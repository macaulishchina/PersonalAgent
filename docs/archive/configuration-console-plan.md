# 系统配置后台与扩展插件管理实施计划

状态：实现完成，自动检查与隔离安装验收通过；生产切换单独安排。当前接口及运维说明见 `src/assistant_runtime/core/configuration/README.md`。

本轮实现已覆盖：模块静态配置声明与共用默认值、类型/嵌套/条件/关联表单、模型和账号入口、私有凭据及环境来源、MCP/技能/扩展资源、跨文件事务与恢复、限定配置修复、独立管理进程、等待/撤销/强制应用、异常子进程清理、应用记录持久化和两种部署默认启动。网关等外部部署始终保留显式步骤，需操作者核实后确认，不自动管理容器。

## 1. 目标与架构

新增必备核心配置插件 `configuration`，slim 与 standard 默认安装、启用，不能通过管理页面关闭。两种部署共用同一后台和配置接口。

面向用户统一称为“系统配置”。核心能力按功能组织，不设置“核心插件”导航，不要求用户理解内部插件名称。扩展插件保留独立的管理入口，展示安装、启用、依赖和配置状态。

这一界面组织不改变内核插件架构：配置、校验与业务逻辑仍由所属模块负责。配置后台统一装配，不集中实现模型、媒体、设备等业务规则。

同一实例使用两个进程：

- **管理进程**：配置后台、管理员鉴权、配置事务、业务进程启停及应用结果检查。
- **业务进程**：Agent 执行与实际启用的对话、任务及扩展能力。

管理进程不依赖模型授权、聊天页面或业务插件启动成功。业务停止、重启或启动失败时，配置后台保持可用。统一启动命令和服务安装流程管理两个进程，无需用户分别启动；两者不形成两套业务实例，也不启动第二套 Agent 执行循环。

管理进程通过私有本地通道管理业务进程，网页不提交任意 shell 命令。进程生命周期由应用装配负责，配置插件调用明确的管理接口；内核不引入 Web、供应商或业务依赖。

## 2. 界面组织与统一配置声明

### 按功能组织系统配置

| 页面 | 内容 |
| --- | --- |
| 总览 | 管理与业务状态、已应用版本、待应用变更、错误及处理入口 |
| 基础与访问 | 实例信息、路径、管理地址、管理员登录、可用入口的访问设置 |
| 模型与账号 | 供应商、API／原生账号、模型别名、用途绑定、推理参数、回退配置 |
| 执行与用量 | 公共执行、并发和队列、用量与预算、防失控策略 |
| 对话与任务 | 对话行为、后台任务与调度的系统设置；具体对话和任务记录仍在原业务界面 |
| 通知与事件 | 通知渠道、投递策略、事件处理设置；通知收件箱仍在原业务界面 |
| 记忆与文件 | 记忆设置、工作目录、产物与保留策略 |
| 外部连接 | 第三方 MCP 等公共连接配置、鉴权状态及验证结果 |
| 扩展插件 | 已安装扩展、功能说明、启停、依赖、配置和健康状态 |
| 变更与应用 | 脱敏差异、校验、保存、应用进度、历史及恢复入口 |

默认页面展示常用项，较少使用的配置放在同页“高级设置”中。必要技术标识可出现在诊断详情，不作为主要导航或表单标题。

系统功能是否启用与其内部属于核心插件分开处理：必备基础能力不能关闭，可选功能可以通过“启用记忆”等功能开关控制。未安装的可选功能显示依赖与不可用原因，不渲染为可正常使用。

扩展插件的详细配置统一位于其管理页。系统页面可提供跳转或只读摘要，不维护第二套独立表单和数据来源。同一字段在整个后台只有一个配置身份和写入入口。

### 配置声明与覆盖范围

扩展公共插件声明，提供可序列化配置 Schema 和界面元数据：字段名称、说明、默认值、约束、分组、敏感性、可修改属性及应用影响。框架维护系统功能分组，模块声明字段的所属分组；外部包不能借此冒充必备系统能力。

所有内置模块补齐配置声明，外部插件使用同一规范。读取配置描述不要求启动插件或导入其可选运行依赖。保存与启动复用所属模块的校验入口，不能形成两套不一致的规则。

覆盖核心配置、核心能力配置和扩展插件的全部声明字段。复杂配置使用结构化编辑，必要时提供限定范围的高级文本编辑，仍执行同一套校验。生命周期或外部工具管理已有自己的接口时，通过该接口操作，不绕过模块的版本、权限和校验。

`config/` 继续是配置来源，保留显式 TOML 拆分。MCP 等 JSON 注册表由所属模块提供适配；实例技能等文本资源通过明确声明的资源接口管理。不提供任意服务器文件编辑器，不维护数据库中的第二份生效配置。

第一版管理已安装扩展，不实现在线插件市场或自动安装依赖。插件开关变化先计算完整依赖影响：缺失依赖阻止启用，关闭被依赖功能时列出依赖方，联动变更必须由用户确认。

## 3. 登录、凭据与配置保存

默认监听 `0.0.0.0:8047`，地址及端口可配置。使用独立管理员凭据、会话及 Cookie 名称，不复用聊天网页登录。管理接口只面向操作者，不因存在模型工具接口而自动授予助手修改系统配置的能力。

首次初始化生成随机管理员口令，写入实例私有位置，由本机 CLI 获取；不使用默认密码，不允许未认证的远程首次接管。提供本机口令重置入口。支持 HTTPS 反向代理部署，并明确受信代理与请求来源校验；局域网 HTTP 本身不提供传输加密。

凭据处理：

- 支持录入、更换和清除，只显示已配置状态及来源，不回显已有密钥。
- 复用现有私有凭据存储和解析机制；配置保存引用，原生账号凭据继续由原生账号模块管理。
- 外部环境提供、后台无法修改的凭据明确标记来源及限制，不声称已修改实际生效值。
- 密钥不进入普通日志、配置差异、浏览器回显或普通配置导出；含凭据的恢复材料采用私有权限保存。
- 原生账号授权仅复用已实现流程；尚未实现的第三方 MCP OAuth 明确显示不支持，本轮不另建授权系统。

编辑状态明确区分：

1. **草稿**：尚未保存。
2. **已保存待应用**：配置文件已更新，业务进程仍使用旧版本。
3. **已应用**：业务进程加载了对应版本，并完成必要启动检查。

保存前校验整个实例，检查字段、插件依赖、能力绑定、端口冲突等。配置版本覆盖相关文件内容，检测其他浏览器或本机编辑造成的冲突；冲突时要求重新加载或重新整理变更，不能覆盖更新。

多文件保存使用暂存、事务日志和私有备份。异常中断后先恢复到完整版本，再允许业务启动。保留未修改字段、显式 include 关系与文件组织，尽量保留 TOML 注释。密钥变更纳入相同的版本与恢复流程。

审计记录操作时间、来源、配置版本、变更字段和结果，不记录密钥值。保存失败不能修改运行状态或显示已保存成功。

## 4. 应用、重启与恢复

第一版统一通过业务进程重启应用配置，不实现通用热更新。页面先展示变更与影响，再提供两种选择：

- **等待执行完成**：暂停接收新执行，让当前执行继续；保留回答澄清的能力，展示等待对象，并允许撤销等待。撤销后恢复执行准入，保存的配置仍标记为待应用。
- **强制终止并重启**：额外确认受影响执行，先请求取消，超过有限等待后终止本实例拥有的执行进程，不操作无关进程。未确认的外部操作标记为结果未知，不能声称已撤销，也不能在重启后自动重做。

等待、取消与关闭均复用公共执行生命周期接口。排队工作的记录持久化保存；强制或异常重启会核对未派发即时工作，不新增自动重放。任务计划仍按所属模块原有规则处理，禁用功能不会删除记录。不能将应用重启作为已执行任务取消成功的证据。

应用步骤：

1. 校验并冻结待应用版本；处理中不再接受会改变该版本的配置写入。
2. 按用户选择处理活动执行。
3. 启动业务进程，核对加载版本及必备能力就绪状态。
4. 成功则标记已应用；可选能力启动失败时明确展示“已应用但部分功能不可用”，列出受影响功能。
5. 必备能力失败则保留管理后台、脱敏诊断与失败状态，不进入无限业务重启循环。

提供显式恢复上一个已确认配置的操作，包含必要的私有凭据恢复。恢复配置不自动重放失败或未知执行。

管理进程独立保存最小启动信息：实例定位、监听地址和管理员凭据引用。普通业务配置损坏时仍可进入修复页面，不回退到未经认证的入口。管理自身配置无法解析时提供本机修复方法，不猜测地址或绕过登录。

修改管理地址、端口等自身设置时单独提示目标地址和连接中断，应用后允许短暂重连；普通业务重启不影响管理页面。改变实例位置、存储位置等涉及数据迁移的字段必须声明额外约束，不把修改路径伪装成已经完成数据迁移。

## 5. 实施顺序、验收与交付

### 实施顺序

1. 完善公共配置 Schema、功能分组元数据、资源配置接口和凭据标识，并覆盖现有配置项。
2. 建立配置版本、整体校验、事务保存、备份恢复及审计能力。
3. 分离管理与业务进程，接入统一执行准入、取消、关闭及启动检查；与 slim／standard 的宿主重构统一实现，不另建平行宿主。
4. 实现按功能组织的系统配置页面、独立管理员登录、扩展插件管理及完整配置编辑。
5. 接入两套初始化预设、安装脚本、公共 CLI，更新架构、插件开发与运维文档。

### 必须验收

- 无模型配置、业务配置损坏、扩展依赖缺失或业务进程退出时，配置后台仍可访问并提供修复路径。
- 系统页面按功能组织，不以核心插件清单作为导航；扩展插件有独立管理入口，同一字段没有重复配置来源。
- 核心及全部内置模块的声明配置可查看、编辑、校验、保存和应用；只读或需迁移字段明确解释限制。
- 独立安装的扩展包仅提供标准声明即可出现配置界面，无需修改中央页面；缺依赖时仍能查看诊断。
- 并发编辑、外部文件修改、多文件写入中断、磁盘失败及恢复不会导致半份配置被加载。
- 密钥录入、更换、清除、外部来源识别与备份恢复正确，页面、接口及日志不泄露密钥。
- 未登录访问、跨站写请求、会话隔离及代理来源检查有效。
- 等待完成、撤销等待、强制终止、启动失败与显式恢复都有明确状态；未知操作不会重放。
- slim 与 standard 共用后台、配置接口和 CLI；slim 不因此加载聊天、设备、记忆或任务调度。
- 现有模型回退、共享用量保护、任务续跑、通知归属、媒体及设备能力回归通过。
- 从仓库锁定安装和发布包安装均能启动后台，并完成最小实例配置；运行中不依赖开发环境或前端开发服务器。

### 交付边界

交付配置后台、公共配置声明与接口、管理／业务进程生命周期、初始化及安装流程、私有备份恢复、自动测试和使用文档。

本计划不增加模型付费验收、真实媒体删除或设备动作；语音继续停用，执行沙箱仍在本轮范围之外。开发和独立验收在隔离工作区完成，保留生产数据、凭据及现有配置含义。确需格式调整时提供一次性转换和校验，不维护长期双格式。

生产进程结构切换独立安排，不随开发或文档保存自动执行。
