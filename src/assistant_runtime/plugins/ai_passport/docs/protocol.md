# 终端协议 2 与模块边界

协议 2 的服务端与固件正在本次重构验收中；0.2.0 开发固件已刷入 Dell 上的 PP
并完成首次启动检查，尚非完整硬件验收。不能与协议 1 固件混用，PA 生产服务尚未切换。
开发清单见 [terminal-rebuild.md](terminal-rebuild.md)。

## 所有权

| 模块 | 所有权 |
|---|---|
| conversation | 独立会话、输入收据、澄清与引导原子检查、历史游标及会话图片授权 |
| Pi | 唯一执行循环、工具、取消及供应商明确的消息阶段证据 |
| speech_io | 有界开流缓冲、序号、音频量、输入结束及流清理 |
| aliyun_speech | 阿里协议、字数／秒数的预留结算、音色与语速 |
| notifications | 任务通知及终端收到／播放／已读收据 |
| ai_passport | 设备身份、连接、配置版本、分句播报与播放收据 |
| app + configuration entrance | 私有控制通道、管理员管理及公共 HTTP/WS 入口 |
| firmware | 按键、固定预算Flash缓存、显示、PCM、Wi-Fi、NVS 与休眠 |

主机侧入口 `plugin.py` 负责配对及 WebSocket 接管，`protocol.py` 定义允许的指令字段、
帧编码和传输上限，`connection.py` 管理每条连接的输入、订阅与播放生命周期。
支持实时预览的设备在 WebSocket 握手中发送 `X-PP-Live-Previews: 1`。启用图片和离线缓存时，
`display.py` 在最终消息前逐张发送 `message.preview`，包含消息 ID、修订、轮次、图片 ID、
宽高、RGB565 小端像素的 Base64 和 SHA-256。每帧最多 64×32 像素；生成失败只影响该附件。
PP 校验后逐张排队写 Flash 并核对写入结果，预览随所属轮次回收。设备凭据与播放收据由 `repository.py` 管理，配置归 `settings.py`。

插件只通过 PluginContext 访问已声明能力。会话由服务端绑定，设备不能提交任意
session_id、模型、供应商密钥、执行身份、文件路径或外部图片 URL。

## 地址与数字配对

PA 业务根地址例如 `http://服务器:8047`，对应：

- POST `/entrances/ai_passport/pair`
- WebSocket `/entrances/ai_passport/stream`

9443 用于分发固件。PA 业务地址与公开 CA 随固件构建预设，热点页面只填写 Wi-Fi。
HTTP 连接可直接建立。使用 HTTPS 时，设备须先取得有效时间，再校验证书和服务器名称。
重新刷机和主动重新配网对已有设置的影响见[终端部署说明](../firmware/apps/pa_terminal/README.md)。

设备随机生成并持久保存自己的 ID 和凭据；POST 内容仅为
`{protocol:2,device_id,credential}`。未配对返回八位十进制码及到期时间，码十分钟有效。
操作者在 PA 后台输入该码，服务端消费码并绑定独立会话；设备再次查询得到 paired。
重复查询不能延长现有配对码寿命；确认丢失可以核实已配对身份，不创建第二个会话。

WebSocket 使用 Authorization Bearer 与 X-Device-Id，拒绝 Cookie 和 Origin。
同一设备验证成功后可接管旧连接；接管尚未完成时，并发握手返回 HTTP 409。撤销立即断开设备，已经接受的业务继续。配对材料和供应商密钥不下发到浏览器。

## 有界消息与历史

每条 JSON 的 UTF-8 字节数最多为 16 KiB。发送端按实际传输的编码检查长度，中文直接以
UTF-8 传输。

| 上行 | 下行与约束 |
|---|---|
| input.begin(request_id, mode, audio_ids?) | input.ready(request_id, max_audio_bytes)；先绑定目标及共享工作额度，再接受序号音频 |
| 二进制音频 | 4 字节大端序号 + PCM16。启用 `audio_ids` 时在序号前带 4 字节全 FF 标记和 16 字节 UUID |
| input.finish(request_id, frames, confirmation_required) | recognizing、transcript、input.receipt；标记需确认的输入等待操作者选择 |
| input.confirm(request_id) | 仅提交服务端保存的待确认转写，重复请求查持久收据 |
| input.transcript(request_id, offset) | 仅待确认输入可读，每页 80 字、全文长度及下一偏移；不能读取其他设备或已提交输入 |
| input.cancel / input.receipt | 取消未提交输入或查询收据，不重发未知业务 |
| image.stream.open(request_id, message_id, image_id, width, height) | PA 在 hello 声明 `image_strips` 时可用。按设备的图片区域等比缩小，最大 216×194，返回尺寸、字节数及完整 SHA-256 |
| image.stream.next(request_id, row) | 从第 0 行顺序请求。每次只传一块，PP 校验并画完后请求下一块 |
| image.stream.close(request_id) | 释放该次传输。翻页使用新的请求编号，迟到的旧分块会被丢弃 |
| playback.stop | 结束本条播报；不提供继续、恢复或重播操作 |
| playback.credit(generation, bytes) | 设备按内存授予 8–24 KiB 播放窗口。二进制为 4 字节大端播放版本 + PCM16 |
| playback.completed(generation, pcm?) | I²S 排空后确认，可附接收、写入和缓冲见底统计 |
| execution.cancel(request_id) | 使用现有会话取消机制，停止播报不代替取消执行 |
| notifications.list(before, request_id) | 有归属的任务结果、小页及游标；主动读取不触发播报。PA 在 hello 声明 `notification_list_ids` 后，查询响应原样返回请求 UUID，主动推送不带 UUID |
| notification.page(id, revision, offset) | 返回同一通知的id、revision、offset、text及next_offset；不使用语音内部消息id |
| notification.receipt | received、played、read 独立收据 |
| configuration.reload | 获取已应用的文件配置，不读取未保存的后台草稿 |
| configuration.applied(versions, actual) | 持久应用的字段版本；只回显音量、输入模式、保持在线等无敏感本地偏好 |

握手从当前事件游标开始接收实时变化。重连或游标过期后只接收后续事件。
实时消息用 `message` 下发，长正文余下部分用 `message.part` 顺序送达，每块最多 1600 个 Unicode 字符。
终态消息携带同轮分组、修订和偏移，流式文字仅用于即时显示。返回主页保留已接受的工作。
待澄清问题保持独立的有界显示缓冲，返回主页
后仍可上下查看并回答；问题归属及回答接受继续由会话服务管理。

图片来自现有文件资源设施。会话先核对消息及图片归属，再按屏幕尺寸生成光栅图像；没有 URL
下载代理，也不因图片显示失败重新执行截图等工具。图片工具正文不作为聊天正文显示。

高清分块为下行二进制消息。20 字节头依次为 4 字节全 FF、4 字节请求编号、2 字节起始行、
2 字节行数和像素 SHA-256 的前 8 字节；整数使用大端，后接小端 RGB565 像素。PP 检查编号、
行号、长度和摘要。高清像素逐块刷到显示屏，状态栏刷新保护已经刷出的内容。全图摘要通过
后才允许把采样到的小预览写入离线缓存；离线预览至多 64×32。

历史导航由设备的存储工作线程读取记录和字符窗口。每次查看图片关联一个请求编号，退出后丢弃迟到条带并释放缓冲。

## 流式文字、分句播报及取消

文字沿用已提交的会话增量。消息阶段保存在公共 `presentation.text_ranges` 中，以 Unicode
字符偏移关联正文；Pi 协议字段仅在 Pi 适配层解析，不放进模型上下文或工具参数。

- 提供 `final_answer` 的供应商：完整确定句可以在消息结束前播报。
- `commentary`、思考块、未确定的阶段：不会提前朗读。
- 不提供阶段的供应商：正常完成、确认最终回复后开始播报，不根据文案猜测。
- 阶段冲突、正文被替换、失败／取消／结果未知：撤销后续可播范围，保留实际文字与业务证据。
- 简短模式最多合成 200 字，完整模式继续分页。已确认的长句优先在标点或词间拆分，必要时按长度拆分。只清理播报用文本里的 Markdown、链接地址和表情，屏幕仍显示原文。

每条回复共用一次 `playback.start` 和一个有界接收窗口。合成服务按小段工作，PA 可以为下一段
预读一个供应商音频帧，前段传完后复用同一窗口下发，语音流名额不足时按顺序合成。
`playback.end` 表示下发结束，包含已处理到的源文本偏移。PA 在 `hello.playback_window` 公布上限，
旧版缺字段时仍用 8 KiB。PP 按可用内存借用，首播及断流恢复等预缓冲达到阈值再播，结束时短尾仍会播出。
正常来流下，8 KiB 窗口约攒 100 毫秒音频，24 KiB 约攒 469 毫秒。PP 在首播和断流恢复时测量 PCM 到达速度。持续低于播放速率的 80% 时，目标提高到 2 秒音频；两秒播放量内连续见底时提高到 3 秒。凑齐基础预缓冲后，额外等待最迟在本轮收到首包后的 6 秒结束；来流不足实时速率一半或连续见底时为 8 秒。收到结束标记或达到实际可缓存容量会提前开播。复用已有 SRAM／Flash 队列，所需播放速率仍是 48,000 字节/秒。设备在 I²S DMA 和 FIFO 排空后才回
`playback.completed`，PA 随后发 `playback.finished`。供应商中途失败时让已收到的 PCM 播完，再用
状态栏提示语音暂不可用，保留文字。按下 OK 终止当前播放版本并关掉预合成流，后续增量不会重新播报。

PA 公布 `hello.playback_metrics` 后，PP 在播放完成时回传 PCM 字节数、CRC32 和缓冲见底次数。
按同一连接、播放版本核对 PA 已发、PP 已接收和 I²S 驱动实际接受的 PCM。未结束且 DMA 已耗尽时
每次重新缓冲计一次，正常句尾排空不计。串口 `pp.audio` 可读最近一轮统计。统计不保存音频。

播放收据复用私有仓库，记录 played、stopped、unavailable 或未知。重连不重播历史音频。
会话增量使用持久事件游标；公共事件只作唤醒，丢唤醒时三十秒恢复核对，不高频扫描数据库。
ASR 转写使用独立更新信号；仅最终转写能进入会话。

## 配置版本与恢复

文件是唯一目标配置来源。`ai_passport.devices.<device_id>` 为设备覆盖值，未填写字段使用
插件默认设置。Wi-Fi 用优先级 1—5 的命名表配置，线上转换为有序列表。
`brightness` 为40—100的背光值，默认65；`text_size` 为16或18，只作用于正文。
两档原生字库存放在Flash，设备按真实行高重新分页，不占用额外整屏图层。

下发 `configuration.fields.<field>={version,value}`。只有实际目标值变化才产生新版本；
重连和设备菜单“重载配置”不会重置没有远程修改的本地偏好。移除原网络覆盖时下发 null
解除云端管理，不删除设备最后可用的网络。设备只在安全空闲点持久应用网络变更，
保存成功后才确认版本。服务端只保存派生版本、值指纹与非敏感回执，不存第二份目标配置。

识别开始前或识别期间取消输入，连接负责关闭识别流并释放名额。开始向会话提交后，
即使无线连接中断也等待该次提交收尾，重新连接的设备使用写入 NVS 的输入 ID 查询持久收据。
已经接受的任务继续执行，结果未确认时禁止用新 ID 重做。
超限输入先由会话模块持久保存完整转写，再通知设备进入 `review`，尚不进入模型、任务或记忆。
设备只缓存当前文字页；确认菜单默认“丢弃”，另可明确发送或查看全文，查看后返回仍默认丢弃。
断线或重启恢复 `review` 时继续等待明确选择；确认只使用保存的原文，不接受替换正文。
发送确认丢失后查询同一输入收据，不重新识别或创建新输入。明确丢弃清除待确认正文，
确认接受后正文沿用原会话存储，不在待确认记录保留第二份。
ASR 失败不进入执行；TTS 失败保留文字和业务结果；计量失败阻止付费调用，不影响只读历史。
原始音频只在有界内存中，默认不落盘、不进入普通日志。

任务页读取仅锁定一个有界只读请求，不锁住导航。改变列表选择或返回即丢弃本地读取等待；
迟到页按通知ID、修订和偏移核对。格式错误、明确失败或15秒读取期限到期后可再次选择；
没有自动重试，也不因读取失败重做后台任务。只有匹配且内容有效的页面才标记已读。

收音同时受时间和实际PCM字节数限制。服务端input.ready给出实际max_audio_bytes，
设备取自身60秒上限与该值的较小者；16kHz单声道PCM16的60秒为1,920,000字节。
设备将 20 毫秒采样块合为最多 40 毫秒的一帧，松开按键时发送剩余的短帧。每个录音包
最多 1,280 字节 PCM，带标识时总长 1,304 字节，放入一段 WebSocket 数据和 TLS 记录。
WebSocket 发送与接收缓冲各 1.5 KiB，TLS 保留 16 KiB 入站记录兼容性，出站记录限制为
1.5 KiB。收音和播报开始前释放无人借用的 SRAM 缓存。任一录音上限先到即停止，
达到字节上限后仅丢弃界限外的本地尾帧，
已发送的帧保持原序号和完整性，完成转写后仍须明确确认；不能为接受越限流而放宽服务端校验。

PA 在 hello 中声明 `input_audio_ids` 时，终端可在发出 input.begin 后先发送最多一秒
带 UUID 的音频，等 input.ready 到达才使用实际字节额度及发送 input.finish。PA 依照同一
WebSocket 的顺序完成输入准备后才接收音频，仅将 UUID 匹配的音频交给当前识别流，
回执的网络发送不阻塞上行读取。未启用此能力的连接走原有就绪回执流程。终端在发送
input.finish 前持久保存输入 ID，之后再掉线按原收据核对。

服务端区分speech_input_gap、speech_invalid_pcm、speech_input_limit及speech_input_deadline。
错误关联已绑定设备的输入ID；关闭后的残留PCM不再刷出一串新错误，取消和收据仍使用
原持久输入记录。新输入必须重新prepare并取得自己的额度，未知ID不能沿用失败输入权限。
日志只记阶段、序号、字节和上限等元数据，不记录PCM或识别正文。

终端为结束或取消指令保留发送队列空间。短时无线发送落后时，PCM 留在有界收音缓冲。
缓冲耗尽时停止收音，仍按原序号上传连续前段，并以 `confirmation_required=true`
请求待确认转写。停止收音后，上传连续 15 秒没有发送进展才取消。PA 按已接收的有效 PCM 延展传输期限，音频字节上限独立执行。
如果取消指令也无法排队，关闭当前连接，由服务端清理未提交输入。
PA 等待识别供应商时，每个流最多暂存 8 秒 PCM 和 512 个分块，仅占用内存。
录音未能开始时，`speech_busy` 关联被拒绝的请求 ID，终端释放本地录音状态。旧终端若再
取消该请求，只收到对应的取消回执。供应商在提交前中断或超时时，服务端关闭识别流并取消
该输入，之后才向终端报告原因，允许下一次由用户发起录音。

设备凭据和会话绑定持久化，普通服务/设备重启不重新配对；八位码只用于首次绑定。
同一设备验证成功的新连接接管旧传输，旧连接关闭不会取消已接受工作，也不能移除
替代连接的登记。错误凭据和已撤销凭据不能接管，其他设备仍受连接数量上限限制。
终端每次建连都分配独立代次。新的 WebSocket 收到并验证当前代次的 `hello` 后，才可发出业务指令。
收发队列核对代次并丢弃旧帧；握手后的首轮请求仍可查询原输入 ID 的收据。
终端断开时只收尾本地录播；已发出 `input.finish` 的输入转为待核对，重连以服务端收据为准。
入口代理两端均使用WebSocket心跳，避免设备重启后的旧TCP占位永久在线。

### 顺序流缓存

录音和播报共用通用 FIFO 接口，优先使用各自的分块 RAM 队列。队列达到四分之三时，
工作任务可把最早的完整页转存到临时分区。每页 3,840 字节有效数据，在一个 4 KiB
扇区内附带加密元数据。3 MiB 共有 768 个扇区，最多容纳 2,949,120 字节有效数据。
同一时间一个流可以借用这块 Flash，其他流仍可使用各自的 RAM。流在可选扩容前一次预留三块 3,840 字节的 RAM，分别供后台 I/O、当前读页和下一读页使用。
预留与可选扩容均留出 32 KiB 系统堆。整组预留失败时使用 RAM 队列。关闭后由工作任务归还。

每次从 RAM 转存成功，播报端可补回对应字节的接收额度；从 Flash 读出时不会重复发放。
初始额度仍取决于已分配的 RAM，录音和播报的基础窗口独立于 Flash 容量。
`hello.playback_progress` 开启后，PP 至多每秒报告当前代次累计写入 I²S 的字节。
PA 等待额度或排空时，只有严格递增且在已发送范围内的进度才能延展 30 秒的停滞期限。
旧 PA 使用原播报 RAM 窗口。一个会话用完可写扇区后，继续按顺序排空并通过 RAM 窗口传输。
读者始终先消费较早的数据。设备空闲时逐扇区准备可写空间，音频过程中只向空白扇区编程。
分配或编程失败会保留 RAM 中的原数据并停止该流继续溢写；读取或认证失败时终止该次操作。
每个使用 Flash 的流有独立的临时 AES-CCM 密钥，密钥只在 RAM，
关闭、取消、重启后都不会从旧扇区恢复或重发音频。

## 本机滚动历史

- PP 将实时收到的用户提问、回复及带图消息写入 Flash。相同版本重复投递时复用已有记录，流式草稿只在屏幕上显示。PA 和 PP 之间没有历史目录、翻页、重放或预取协议。
- 主页上下键、长文翻页及跳到最新都在本地完成。断网和重连保留当前阅读位置，离线期间发生的消息不会出现在本机。0.2.1 已保存的目录和内容从本机读取一次，已有预览沿用原键。
- 翻到附件即进入图片页，优先显示本地预览，在线自动请求当前图的高清条带。没有预览且离线时提示「此图未保存预览」，可以继续上下翻页。完整校验高清条带后可保存最多 64×32 的小预览供下次使用。
- 历史独占 1 MiB LittleFS 分区。每个对象按 4 KiB 块保守计费，最多使用 960 KiB，预留 64 KiB 给文件系统元数据、原子替换和回收日志。文件系统提前报告空间不足也会触发同一回收策略。另有独立的 3 MiB 临时音频区。
- 写入超出预算时按各轮次最早记录的顺序，清掉最旧的一半可回收轮次（奇数向上取整）。同轮的提问、回复、长文分块和图片预览一起删除。无轮次的独立消息单独计数。当前写入的轮次保留；单轮独占预算且无法再容纳的部分提示保存失败。
- 回收先持久化待删除的轮次，断电后继续完成原批次。记录按服务地址、设备及绑定隔离。关闭本地历史停止读写；配置、设备凭据和业务收据独立保存。
- Flash I/O 由缓存线程执行，优先服务录音和播报。正文等待写入的队列有界，超过容量会提示该段未保存。RAM 可回收的已提交对象最多两块，共 4 KiB。

### 应用缓冲的借用与归还

- 按下录音键先预留两个 1,304 字节的上传包，可在收音期间循环借还。随后借齐 32 帧 PCM 的容量（640 ms），分为 8 块；松开后允许当前帧完成，
  排空后归还。取消会使旧帧失效并归还整组。键回调仅标记松开，不执行分配或释放。
- 播放开始时借齐 8 KiB 窗口，分为 4 块，成功后才发放播放额度。播放完成或取消时归还，
  已交给 I2S 的一段由音频任务持有，旧段完成回调不能给新段补发额度。
- 建连用配置和 TLS 证书是独立借用对象。配置在 WebSocket 初始化前归还，
  自定义 CA 按实际长度保留至连接销毁。保存的配置和 NVS 格式保持原有结构。
- USB 的只读命令 `pp.memory` 报告各类应用缓冲的持有字节、可回收字节、峰值和分配失败次数。
  正在读写的缓冲由原所有者归还。当前可回收量来自无人借用的 RAM 历史缓存。
  `displayed_image` 表示已经绘制的像素字节。查看高清图时它与仍然借用的 `image` 字节分开统计。
  空闲堆和最大连续块还反映系统、驱动和任务栈的开销。
