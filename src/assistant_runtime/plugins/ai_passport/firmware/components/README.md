# 板级组件

`bsp/` 提供板级驱动和引脚定义。驱动来自 `../upstream.json` 锁定的 FoloToy 提交，本项目对 ES8311 音频驱动的调整记录在其中的 `adapted_files`。当前驱动的文件哈希见 `../bsp.sha256.json`。

`pp_board/` 复用这些驱动，负责 PA-Terminal 和 PPDemo 共同使用的板级生命周期操作。两款应用各自决定何时休眠，先确认业务空闲、停止 PCM 和无线访问、完成必要的持久化。质检应用还可先设置定时唤醒。

**深睡交接**由 `pp_board_enter_deep_sleep()` 单向执行。ES8311 停止工作后，三个共用 ADC 的按键交回数字输入，确认全部松开并启用 GPIO 低电平唤醒。CW2017 和 ES8311 完成最后一次 I²C 通信后，I²S 和 I²C 引脚进入高阻状态。最后持有 LVGL 锁，停止 ST7789 并保持引脚，再进入深睡。交接失败会在串口记录具体阶段并重启。唤醒后由应用重新初始化驱动。

浅睡属于质检应用的可逆测试，保留音频唤醒和背光恢复。主机 C 测试通过逐阶段注入故障核对深睡调用顺序及重启边界。唤醒电平、休眠电流和真机恢复仍需实测。

组件由 ESP-IDF Component Manager 按工程的锁文件解析。变更 `bsp/` 时需更新适配来源和哈希，检查对应驱动及硬件。
